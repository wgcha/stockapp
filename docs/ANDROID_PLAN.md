# Android 앱 개발 계획

기준일: 2026-10-08. 사용자가 Android 설치형 앱, 토스증권을 참고한 가독성과 색감,
`wgcha/stockapp` 저장소 업데이트, 계획·개발·검수까지 요청했다.

## 목표와 완료 기준

본인용 투자 가이드 앱 0.1을 만든다. Kotlin·Jetpack Compose 화면과 기존 Python 분석 코드를
연결한다. 실제 매매는 증권사 앱에서 직접 한다. 앱과 API에는 주문 실행 기능을 추가하지 않는다.

- 설치 가능한 디버그 APK를 빌드한다.
- 외부 인증정보 없이 데모 모드에서 투자금·보유·관심종목을 저장하고 재시작 후 복구한다.
- 서버 주소와 개인용 API 접근 키로 연결하고, 저장·조회·가이드 요청을 실제 HTTP로 처리한다.
- 토스 API 키는 서버에만 저장한다. Telegram 토큰 없이 모바일 API를 실행할 수 있다.
- 시세 미연결·자료 부족·미승인 전략·통신 실패를 구분하고 조회하지 않은 가격·손익을 만들지 않는다.
- Android 알림 권한을 처리하고 평일 가이드 확인 알림을 켜거나 끌 수 있다. 첫 버전은 기기 로컬
  리마인더다. 운영체제에 따라 지연될 수 있으며 서버의 실시간 투자 신호 푸시로 표시하지 않는다.
- Python 회귀, API 인증·입력·저장 테스트, Android 빌드·검사 및 가능한 기기 실행을 검수한다.
- GitHub에 계획, 소스, 운영법과 검증 결과를 커밋한다. 인증정보·운영 DB·개발 캐시는 제외한다.

## 화면과 사용 흐름

네 탭은 `오늘`, `보유·관심`, `알림`, `설정`이다. 밝은 중립색 바탕, 파란 주요 버튼, 큰 핵심 숫자,
충분한 여백, 짧은 설명을 사용한다. 자료 부족은 글자와 상태 표시를 함께 사용한다. 상세 판단 근거는
펼쳐 읽는다. 색만으로 의미를 전달하지 않으며 작은 화면·큰 글자·다크 모드를 고려한다.

데모 모드는 예시임을 항상 표시하고 실제 연결 모드와 저장 공간을 분리한다. 첫 실행은 데모로
시작할 수 있으며 사용자가 연결 정보를 입력하고 확인한 뒤 서버 모드로 전환한다.

## 구현 분담과 순서

1. Sol: 기존 코드·도구 확인, API 계약과 완료 기준 확정, 계획 커밋.
2. Luna A: 독립 모바일 API와 관련 테스트. 기존 Telegram 흐름의 변경은 최소화한다.
3. Luna B: Android 앱·로컬 데모 저장·API 클라이언트·알림·빌드 설정.
4. Sol: API와 앱 통합, APK 빌드, UI·오류·재시작 확인.
5. Astra: 인증·자료 경계와 사용자 흐름의 독립 검수. 발견한 오류는 담당 구현자가 수정한다.
6. Sol: 전체 검증 결과와 남은 외부 연결 조건을 문서화하고 GitHub 업데이트.

서로 다른 구현자는 같은 파일을 수정하지 않는다. 계약은 [모바일 API 계약](MOBILE_API.md)을 따른다.

## 기술·운영 결정

- Android: Kotlin 2.3.21, Compose BOM 2026.06.00, AGP 8.13.2, Gradle 8.13, SDK 36.
  설치된 개발 도구와 캐시를 사용한다. 최소 Android 버전은 API 26으로 잡는다.
- 서버: Python의 기존 SQLite·시세·가이드 모듈을 재사용하는 개인용 JSON API. 기본 주소는
  `127.0.0.1:8765`이며 외부 운영은 HTTPS 종단과 상시 실행 호스트를 별도로 구성한다.
- 서버 접근 키는 환경 설정으로 공급하며 모든 사용자 자료 API에 인증을 적용한다.
- 앱의 서버 접근 키는 Android Keystore로 보호한다. 토스 비밀키는 APK에 포함하지 않는다.
- 개발용 HTTP는 디버그 빌드의 로컬·사설망 시험에 한정하고 릴리스 연결은 HTTPS를 요구한다.
- 실제 토스 연결은 Client ID·Secret과 출발 IP 등록 후 검증한다. 운영 배포·실계좌 연동·Play Store
  배포·FCM 실시간 푸시는 이 로컬 0.1 완성과 별도의 외부 설정 및 검증 항목이다.
