## 검수 중 고친 문제

- Astra가 같은 API 데이터 폴더에서 데모 자료를 서버 자료로 재사용하는 문제를 재현했다.
  영속 모드 표식으로 양방향 전환과 미표식 기존 DB 인수를 거부하고, 데모 예시는 첫 생성 때만 넣는다.
- Astra가 인증 없는 불완전 요청 하나로 서버가 정지하는 문제를 재현했다. 인증을 본문 읽기 전으로
  옮기고 요청별 스레드와 5초 연결 제한을 적용했다. 미완성 헤더·본문 중에도 정상 요청이 처리됨을 재검수했다.
- 저장된 Android 서버 주소도 요청 직전에 검사하도록 보강했다. 개인 API 키는 Keystore AES-GCM,
  백업 제외, 리다이렉트 금지로 보호한다. 릴리스는 HTTPS만 허용한다.
- 데모에서 서버로 전환할 때 입력 중인 금액·보유·관심 양식을 지우고 서버 값으로 갱신했다.
- 데모 주요 버튼을 실제 연결 설정 화면으로 연결했다. 알림 문구를 실제 평일 09:10 고정 일정과 맞췄다.
- API 36의 상단 시스템 표시줄 여백을 반영하고 작은 화면·큰 글자에서 상태 표시 길이를 줄였다.

## 최종 Android 검사

- `testDebugUnitTest`: 8개 통과.
- `connectedDebugAndroidTest`: API 36 에뮬레이터 UI 테스트 1개 통과. 네 탭, 보유 저장,
  금액 저장 및 액티비티 재생성 후 복구 확인.
- `assembleDebug`, `assembleDebugAndroidTest`, `lintDebug`: 성공. lint 오류 0건, 권고 17건.
  권고는 버전 갱신·KTX 스타일·디버그 전용 HTTP 설정·아이콘 폴더 등에 해당한다.
- 360dp 밝은 화면, 320dp/글자 배율 1.3, 다크 모드 스크린샷 확인. 상태 칩 줄바꿈과
  시스템 내비게이션 버튼 대비를 수정했다. 마지막 테마 수정 후 APK 재설치와 시스템
  `LIGHT_NAVIGATION_BARS` 적용을 확인했다.
- 최종 로컬 APK: `dist/stock-guide-0.1.0-debug.apk`, 19,027,168바이트.
- SHA-256: `4133e41360ea010e364d8f34df63e1f1c5a78f5bd8d866b08560e48fe623952b`.
  로컬 개발 서명 APK의 해시이며 GitHub Actions에서 새로 빌드한 파일의 해시와는 다를 수 있다.

## GitHub의 새 환경에서 재검증

[자동 검사 실행 37803952966](https://github.com/wgcha/stockapp/actions/runs/37803952966)이 성공했다.
검증한 실행 코드 커밋은 `9c64f133f32a6963e0db922004cbe07e56945e15`다.
Ubuntu에서 Python 348개가 skip 없이 모두 통과했고, Android 단위 검사·lint·APK 빌드와 업로드도
성공했다. 이후 커밋은 APK 다운로드 및 이 검증 결과를 적은 문서 변경뿐이다.

[GitHub APK 다운로드](https://github.com/wgcha/stockapp/actions/runs/37803952966/artifacts/11562415768)
아티팩트의 이름은 `stock-guide-debug-apk`, ZIP 크기는 18,008,736바이트다.
최초 원격 실행에서 제거된 SDK `tools` 패키지를 설치하려던 설정 오류를 수정한 뒤 재검증했다.

## 검증하지 않은 외부 조건

- 개인 실물 휴대폰의 제조사별 절전 정책과 예정 시간의 알림 전달
- 실제 Toss 키·IP 등록을 사용한 최신 시세 조회, 실제 계좌 연결
- 상시 HTTPS 서버 운영, FCM 실시간 푸시, Play Store 서명·배포
- 전략의 실제 성과나 자동 매매 효과. 앱은 주문을 전송하지 않으며 미승인 전략의 진입을 허용하지 않는다.

위 항목을 로컬 구현·에뮬레이터 검증 완료와 혼동하지 않는다.
