## 2026-10-08 — 백테스트 입력과 로컬 보고 검증 보강

- `DailyBar` 가격과 4개 백테스트 비용률은 유한한 비-불리언 실수만 허용한다. 모든 비용률은 기존
  `[0, 0.1)` 범위를 유지하며 0도 허용한다. 유한한 극단 입력으로 계산 결과가 무한값이 되면 고정
  오류로 중단한다. 기존 수수료·세금·슬리피지 가정이나 전략 기준은 바꾸지 않았다.
- 인증정보 없이 기존 데이터 디렉터리의 특정 전략·버전 보고를 조회하는 읽기 전용 CLI를 추가했다.
  스냅샷의 저장 시점 지표와 현재 정상 모의일수 진행을 같이 보여준다. 원장 누락은 0일이 아닌 미연결,
  원장·달력 오류는 확인 불가로 표시한다. 다중 DB 조회는 원자적이지 않으므로 안정된 시점이 필요하면
  봇을 멈추거나 백업 복사본을 사용한다. DB 생성·마이그레이션, 런타임 기동, API 접속은 하지 않는다.
- Astra 검수에서 SQLite TEXT/BLOB 금융 수치의 강제 변환 가능성을 찾았다. 정상 모의일수 집계의
  평가·자산·모델 재무 지표는 SQLite `typeof`가 `integer` 또는 `real`인지 확인해 TEXT/BLOB 값이
  정상 근거로 인정되지 않도록 보강했다.
- 2026-10-07 전체 unittest 기록은 총 317개 중 316개 통과, 1개 skip이다. 10월 8일 통합 전체
  unittest는 337개 중 336개 통과, 기존 Windows 심볼릭 링크 권한 문제로 1개 skip이다. Sol이 로컬
  CLI·읽기 전용 동작·백테스트를 검수했다. Astra는 SQL 근거 집계 2곳과 손상 DB 회귀 4개를
  독립 재검수했다. WAL을 포함한 최신 보고 날짜와 근거 수 표시를 확인했고, 로컬 보고 테스트 12개가
  통과했다. 4단계 운영 인수와 실제 전략 실증·승인은 계속 대기 중이다.

## 2026-10-07 — 5단계: 전략 실증 보고·중단 상태 복구

- 사용자 명시 승인 범위에서 5단계 로컬 구현을 진행했다. Luna High 추론 구현자 2명이 전략
  검증·보고와 내부 중단 상태 복구를 나누어 작업했고, Sol이 통합과 독립 검수를 수행했다.
- 검증 보고서에 유한값·자료형·범위 검사를 추가했다. 잘못된 과거 승인 보고서는 조회 시
  중지되며 소유자 재활성화를 허용하지 않는다.
- 정상 모의일 계산은 같은 전략·버전·사용자·날짜의 평가와 자산 자료를 연결하고, 잘못된 날짜와
  미래·휴장일을 제외한다. ORB는 해당 날짜에 저장된 모든 종목 자료를 검사하고 별도의 378개
  완전 분봉 거래 세션 조건을 유지한다.
- 소유자 `전략보고 <ID> <버전>`과 전략현황의 미충족 요건 표시를 추가했다. 보고서의 저장 시점
  모의일수와 현재 원장의 `/30` 진행을 구분한다. 관련 원장이 연결된 신규 활성화는 현재 정상
  모의일수 30일과 확인 가능한 달력을 요구한다. 과거 승인 전략은 현재 일수 재계산만으로 자동
  중지하지 않으므로 운영자는 다시 보고 검토해야 한다.
- kill switch 활성 여부와 사유를 `users.sqlite3`의 `execution_safety_state`에 저장하고 시작 때
  복원한다. 저장 실패 시 안전한 중단 상태를 유지하는 동작을 검증했다. 이 변경 전 메모리에만
  존재한 상태나 저장되지 않은 변경은 프로세스 종료 뒤 복구할 수 없으며, API 상태·손익 등 다른
  transient ExecutionState는 복원하지 않는다.
- 검증: 번들 Python `PYTHONPATH=src;.deps` 전체 unittest **317개 중 316개 통과, 1개 skip**.
  Sol 독립 검수에서 차단 이슈가 없었다. 실제 Telegram 메시지·API·전략 성과자료·배포·연속 운영은
  검증하지 않았고, 실제 전략 승인이나 30 모의일·378 분봉 세션을 증명하지 않았다.
- 4단계 운영 인수는 계속 미완료다. 실제 전략 실증 및 승인도 운영 데이터가 쌓일 때까지 대기한다.

  실제 서버 접근권한·키 교체 절차를 기록했다. 기존 서버 ACL·실제 비밀값을 변경하지 않았다.
