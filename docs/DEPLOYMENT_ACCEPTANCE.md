# 4단계: 연결·운영 인수

2026-09-12 사용자 승인으로 진행 중이다. **운영 인수 완료 상태가 아니다.**
현재 작업 폴더에는 `.env`가 없고 프로세스 환경에도 필수 인증정보가 없다.
Docker 명령도 확인되지 않았다. 실제 Telegram·시세 API 호출, 서버 배포, 연속 운영은 미실시다.
진단 도구 구현·로컬 회귀 통과와 실제 운영 성공을 구분한다. 5단계 로컬 구현은
2026-10-07 사용자 승인 범위에서 구현·통합 검증을 마쳤지만, 전략별 실제 실증과 활성화는
아직 확인하지 않았다. 4단계 운영 인수는 아래 대상·설정·연속 운영 증거가 없어 계속 대기한다.

## 운영자가 준비할 정보

- 실행할 노트북 또는 서버와 설치·접속 방법. 동일 봇 토큰은 한 곳에서만 운영한다.
- 로컬 설정 파일 경로. 토큰·비밀번호를 채팅이나 명령행 인수에 붙여 넣지 않는다.
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_USER_ID`와 허용할 사용자 ID.
- `TOSSINVEST_CLIENT_ID`, `TOSSINVEST_CLIENT_SECRET` 및 공급자에 등록된 출발지 IP.
  시세 조회에도 API 인증이 필요하다. 실거래 활성화와는 별개다.
- `TOSSINVEST_ACCOUNT_SEQ`는 초기 가이드 운영에서는 비워 둔다. 이 값을 넣으면
  기존 계좌 위험 점검 작업이 실제 보유·손익을 조회하므로 별도 범위 확인이 필요하다.

## 노트북에서 준비·점검

아래 `python`은 설치된 Python 3.11 이상을 가리켜야 한다. 현재 개발 환경의 기본 별칭은
실패하여 Codex 번들 Python으로 회귀 검사를 수행했다. 상시 운영에는 운영자가 관리할
Python 가상환경 또는 Docker 설치를 사용한다.

```powershell
python -m pip install .
# 최초 1회, .env가 없을 때만 복사
Copy-Item .env.example .env
# 편집기에서 인증정보와 AGENT_DATA_DIR=E:\work\data 입력
python -m stock_guide_agent.cli --env-file .env --doctor
python -m stock_guide_agent.cli --env-file .env --check-telegram
# 동일 인증정보를 쓰는 다른 실행을 모두 중지한 뒤 수행
python -m stock_guide_agent.cli --env-file .env --check-market
```

`--env-file`은 지정한 파일만 읽으며 상위 폴더를 자동 검색하지 않는다. UTF-8/BOM·주석·
따옴표를 지원한다. 기존 프로세스 환경값이 파일값보다 우선하고, 명시적인 `--data-dir`이
데이터 경로의 최우선 값이다. `${VAR}` 확장과 셸 실행은 하지 않는다.
다른 도구가 만든 값을 재사용할 때는 이 차이를 확인한다. 잘못된 파일은 내용 출력 없이 거부한다.

- `--doctor`: 로컬 설정·달력 로딩 확인. API 호출 및 최신 공지 확인은 하지 않는다.
- `--check-telegram`: `getMe`, `getWebhookInfo`만 사용. 수신 메시지 소비·발송·웹훅 변경 없음.
  웹훅이 등록돼 있으면 폴링과 충돌하므로 실패 처리한다. 자동 삭제하지 않는다.
  별도 폴링 프로세스의 존재나 소유자와의 문답 성공까지 증명하지는 않는다.
- `--check-market`: 토큰 발급 후 `005930` 현재가 응답 형식 확인. 계좌·주문 API 호출 없음.
  토큰 재발급이 기존 실행에 영향을 줄 수 있어 별도 명령이며 데이터 잠금을 획득한다.
  다른 데이터 경로나 서버의 프로세스까지 이 잠금이 막지는 않는다.
  응답 성공이 가격의 최신성·정확성이나 전체 자료 수집 성공을 보장하지 않는다.

진단 결과의 `ready`는 해당 명령의 검사 범위에만 적용한다. 오류 원문·토큰·시세 내용은
출력하지 않는다. 현재 HTTP 오류는 고정 오류로 전달하므로 인증 만료·IP 차단·호출 한도의
상세 원인은 공급자 관리 화면과 운영자가 별도로 확인해야 한다.

## Docker 준비·실행

Docker가 설치된 운영 대상에서 실행한다. 이 작업에서는 실제 image build를 수행하지 못했다.
`.env`의 `AGENT_DATA_DIR=/data`를 유지한다. 포트 공개는 필요하지 않으며 HTTPS 외부 접속이 필요하다.

```powershell
docker compose build
docker compose run --rm stock-guide-agent --doctor
docker compose run --rm stock-guide-agent --check-telegram
docker compose run --rm stock-guide-agent --check-market
docker compose up -d
docker compose ps
docker compose logs --tail 50 stock-guide-agent
docker compose exec stock-guide-agent stock-guide-agent --jobs-status
docker compose stop
```

이미지는 UID/GID 10001로 실행하고 루트 파일시스템은 읽기 전용이다. 이미지 진입점을 고쳐
`compose run ... --doctor`가 올바른 실행 파일의 인수로 전달되게 했다. 로그는 파일당 10MB,
3개로 순환한다. 운영 파일과 비밀 설정·백업·로컬 의존성은 빌드 문맥에서 제외한다.

SIGTERM·Ctrl+C는 종료를 요청하고 진행 중인 폴링과 worker가 끝나면 잠금을 해제한다.
Docker는 60초의 종료 유예를 준다. 긴 작업은 이를 넘겨 강제 종료될 수 있으므로 모든 작업의
정상 종료를 보장하지 않는다. 재시작 시 중단 작업·메시지 상태 복구를 확인한다.
컨테이너가 running인 것만으로 정상 문답·자료 갱신을 판단하지 않는다.

데이터는 `stock-guide-data` 볼륨에 보존된다. `docker compose down -v`는 데이터를 지우므로
일반 중지·업데이트에 사용하지 않는다. 이미지 변경 전에는 봇을 중지하고
[백업·새 경로 복원 절차](OPERATIONS.md)를 수행한다. 볼륨 경로/UID·접근권한·디스크 암호화 및
백업 보관 정책은 실제 호스트에서 확인한다. 본 작업은 호스트 권한이나 디스크 설정을 변경하지 않았다.
달력 보정 파일이 필요하면 운영자가 검증한 파일을 컨테이너에 읽기 전용으로 마운트하고 경로를 설정한다.

## 인수 시나리오와 기록

| 확인 | 통과 기준 | 현재 증거 |
| --- | --- | --- |
| 실제 인증·접속 | 두 연결 진단 성공, 시세 IP 등록 확인 | 설정 미제공으로 대기 |
| 소유자 문답 | 소유자가 봇에 먼저 메시지를 보내 도움말·내 설정·보유·관심·가이드 응답 확인 | 대기 |
| 가이드 전용 | 매매 실행 요청에 증권사 앱 직접 거래 안내, 주문 생성·승인 요청 없음 | 로컬 회귀, 실제 문답 대기 |
| 사용자 분리 | 허용 사용자별 저장값 분리, 미허용 계정·그룹 요청 거부 | 로컬 회귀, 실제 계정 대기 |
| 자료 품질 | 현재가 시각·거래일·출처 대조, 누락 시 보류 표시 | 응답 형식 검사 구현, 실자료 대기 |
| 거래 달력 | 신규 공휴일·특수 장시간 공식 공지 대조 및 필요 보정 | 최신 공지 확인 대기 |
| 재시작·장애 | 설정·메시지 처리 상태 보존, 잠금 해제, 중복 실행 거부, 네트워크 복구 | 로컬 회귀, 호스트 대기 |
| 백업·복원 | 봇 중지 후 백업, 새 경로 복원, 설정·처리 번호 비교 | 개발 DB 검증, 운영 DB 대기 |
| 전략 실증·활성화 | 해당 전략 버전이 정상 모의일수·성과·비용·자료 요건을 충족하고 소유자가 보고서 검토 후 승인 | 로컬 검증 규칙·보고 기능만 확인, 실제 전략 증거 및 활성화 대기 |
| 연속 운영 | 최소 24시간 및 거래일 발송창 1회, 문답·자료 갱신·작업 실패·재시도 확인 | 대기 |

실제 검증 때는 시각(KST), 배포 버전, 진단 결과, 문제·조치와 재검증 결과를 기록한다.
사용자 원문·보유 상세·토큰을 기록에 복사하지 않는다. 원격 메시지 발송·시험 운영은 운영 대상과
허용된 계정을 확정한 뒤 수행한다. 자동화나 상시 봇은 아직 등록·기동하지 않았다.

키가 노출됐거나 교체가 필요하면 봇을 중지하고 공식 관리 화면에서 폐기·재발급한 다음 로컬
설정 파일을 갱신한다. 두 진단을 다시 수행한 뒤 재기동하고 문답을 확인한다.

## 확인한 공식 문서

- [Telegram Bot API](https://core.telegram.org/bots/api#getme): 인증·웹훅 상태 확인 명령.
- [토스증권 Open API](https://developers.tossinvest.com/): OAuth 및 접속 조건.
- [토스증권 시세 API](https://developers.tossinvest.com/docs/market-data): 현재가 조회 계약.
- [python-dotenv](https://pypi.org/project/python-dotenv/1.2.3/): 설정 파일 파싱 패키지.

공식 계약과 코드의 대조는 실제 연결 검증과 구분한다.
