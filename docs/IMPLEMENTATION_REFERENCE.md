# Stock Guide Agent

자연어 투자 요청을 구조화하고, 토스증권 시세·계좌 정보와 공식 시장 데이터를
바탕으로 가이드를 만드는 텔레그램 에이전트의 MVP입니다. **실거래는 프로그램이
실행하지 않으며 사용자가 증권사 앱에서 직접 합니다.** 기존 승인형 모의주문은
내부 전략 검증용으로 유지합니다.

## 현재 개발 상태와 계획

2026-09-10 사용자 요청으로 가이드 전용 범위로 변경했습니다. 범위 변경 전 기준선은
로컬 테스트 202개 통과이며 이후 결과는 변경 기록에 남깁니다. 실제 API 연결, 연속 운영,
전략별 정상 모의일수는 미확인입니다. 아래 주문·승인 설명은 내부 모의검증 기능이며,
기존 실거래 위험 검사의 설명도 실제 주문 지원을 의미하지 않습니다.

- [개발 현황·개선 우선순위·단계별 완료 기준](DEVELOPMENT_PLAN.md)

개발은 단계별로 완료·검증 결과를 보고하고 사용자 승인 후 다음 단계로 진행합니다.
다음 개발은 가이드 중심 문답 정리이며, 이후 Telegram 장애 복구와 보안·운영을
개선합니다. 현재 수동 킬스위치와 모의 승인 대기는 메모리에 있으며, 자동 발송·장 마감 작업의
주말 제외만으로 거래소 휴장일 전체를 판별하지는 않습니다. 상시 운영 전 이 제한을
해소하고 백업 복원과 모의환경 장애 시나리오를 검증해야 합니다.

주문 승인 요청에는 주문금액과 함께 예상 거래비용 및 계산 가정이 표시됩니다. 토스는
수수료·매도세금·5bp 불리한 슬리피지를 반영합니다. 미래에셋은 고객별 계약 수수료를
`MIRAE_PAPER_COMMISSION_RATE`로 설정해야 비용이 완전해집니다. 비용이 미확인된
미래에셋 모의거래는 검증일에서 제외되고, 실거래 주문은 실패 폐쇄 방식으로 차단됩니다.

## 다중 사용자 권한

- `TELEGRAM_OWNER_USER_ID`: 주문 승인·거절·킬스위치 권한을 가진 단 한 명
- `TELEGRAM_ALLOWED_USER_IDS`: 봇을 사용할 회원 ID의 쉼표 구분 목록
- `TELEGRAM_OWNER_CHAT_ID`: 승인 요청을 받을 소유자 개인 채팅 ID(생략 시 소유자 ID)
- 허용 목록에는 소유자가 자동 포함됩니다.
- 회원은 자신의 요청과 가이드를 생성할 수 있지만 주문을 승인할 수 없습니다.
- 승인 코드를 알고 있더라도 발신 Telegram user ID가 소유자와 다르면 거부됩니다.

예시:

```powershell
$env:TELEGRAM_BOT_TOKEN='...'
$env:TELEGRAM_OWNER_USER_ID='900'
$env:TELEGRAM_ALLOWED_USER_IDS='30,40,50'
$env:TELEGRAM_OWNER_CHAT_ID='900'
```

소유자 명령:

```text
승인 <proposal_id> <approval_code>
거절 <proposal_id>
거래중단 <사유>
RESET KILL SWITCH
연구후보
전략현황
전략승인 time_series_momentum 1.0.0
전략중지 time_series_momentum 1.0.0
```

사용자 메시지 예시:

```text
보유 005930 10주 평단 70000원
내 투자금은 1,000만원
관심 005930, 000660, 035420
증권사 토스
증권사 미래에셋
장기안정 60% 단타 40%, 연간 8% 목표
이번 한주는 매일 3퍼센트, 장기안정 60퍼 단타 40퍼, 거래당 손실 0.4퍼,
하루 손실 1.2퍼, 하루 2회, 주문마다 승인
가이드 005930
오늘 가이드
매일 가이드 보내줘
자동 가이드 꺼줘
모의현황
주문 005930 1주 70000원
005930 1주를 7만원에 사줘
```

조건은 한 문장에 모두 넣지 않아도 됩니다. 예를 들어 `장기안정 60% 단타 40%`,
`이번 주는 매일 3% 목표`, `하루 손실은 0.8%로 해줘`를 차례로 보내면 이전 설정을
보존하면서 마지막 조건만 합칩니다. `005930 10주를 7만원에 갖고 있어`,
`005930 어때?`, `미래에셋으로 할게` 같은 표현도 명령어 없이 처리합니다.
`내 투자금은 1,000만원`, `계좌 평가금 1억 5000만원`처럼 말하면 평가금도
`user_id`별로 분리 저장합니다. `내 설정`에서 본인 금액을 확인할 수 있고, 다른
사용자의 주문 배분·손실예산에는 사용되지 않습니다. 실거래 승인 직전에도 해당
사용자의 최신 저장 금액을 다시 읽습니다.

가이드 이후 주문도 `005930 1주를 7만원에 사줘`, `005930 70,000원에 2주
매도해줘`, `005930 3주 7.5만원에 주문해줘`처럼 말할 수 있습니다. `사줘`·`팔아줘`로
방향을 명시한 경우 직전 가이드의 매수·매도 방향과 반드시 일치해야 하며, 다르면 소유자
승인 요청도 만들지 않습니다. 방향을 생략한 `주문해줘`는 직전 가이드 방향만 사용합니다.

`매일 3%`처럼 공격적인 목표는 반복 복리의 연 환산값을 산술적으로 보여주되 예측치로
표현하지 않습니다. 장기 배분이 큰데 일일 목표를 요구하거나, 낮은 거래빈도와 반복
단기목표를 동시에 지정하는 조건도 상충으로 표시합니다. 확인 메시지에는 연간 6~12%·
월간 최대손실 3~5% 같은 보수적 재설정 예시, 거래당·일일 손실 제한, 거래 기회가 없을
때 쉬는 원칙과 미배정 비중의 현금 대기 방식을 함께 제시합니다. 이 수치는 수익 보장이
아니라 사용자가 다시 선택할 수 있도록 보여주는 안전 가드레일입니다.

투자성향과 보유정보는 SQLite에서 `user_id`별로 분리됩니다. 한 사용자가 받은
가이드는 다른 사용자의 주문 근거로 사용할 수 없습니다.
`오늘 가이드`는 저장된 보유·관심종목을 한 번에 평가해 행동, 제안비중, 신뢰도,
거래당 손실한도와 무효화 조건을 요약합니다. 응답 첫머리에는 확보된 가격·수급·거시·
공시·뉴스·해외시장 방향과 종합 신뢰도를 표시하고, 뒤에는 검증된 개인 전략 배분과
현금 대기 비중을 보여줍니다. 이 시황 요약은 규칙 기반이라 별도 LLM 호출 토큰을
사용하지 않습니다. 여기서도 주문은 자동 생성되지 않으며 사용자의 별도 주문 요청과
소유자 승인이 필요합니다. `모의현황`은 본인 계정의 최신 평가금, 일일·누적 손익과
전략 검증 인정일수를 보여줍니다.

`매일 가이드 보내줘`는 투자조건과 보유·관심종목이 모두 있는 사용자만 명시적으로
활성화할 수 있습니다. 기본 발송창은 평일 09:10~09:19 KST이며 환경변수로 바꿀 수
있습니다. Telegram 개인 채널과 마지막 발송 거래일을 `user_id`별로 저장해 같은 날
중복 발송하지 않으며 `자동 가이드 꺼줘`로 즉시 해제합니다. 자동 가이드는 사람이
요청한 `오늘 가이드`와 같은 판단 경로를 사용하지만 주문·승인 요청은 생성하지 않습니다.

각 시황 근거에는 출처명, 범주, 관측 후 경과시간과 원문 링크를 표시합니다. 범주 안에서
서로 반대인 신호가 잡히면 신뢰도를 추가로 낮추며, 오래됐거나 미래 시각으로 잘못 표시된
자료는 계산에서 제외합니다. 특히 최신 가격 또는 외국인·기관·개인 수급 중 하나라도
없으면 거시·뉴스·해외 자료가 충분하더라도 시황을 `자료부족`으로 강제해 신규매수를
차단합니다.

대체종목 검토는 본인 보유·관심종목 안에서만 수행하며 현재 종목과 후보의 모멘텀 신호,
후보 신뢰도를 함께 표시합니다. 후보 가격도 5분 이내이고 미래시각 오류가 없어야 합니다.
`다른 종목 검토` 결과 자체는 주문 권한이 아니며, 후보 종목을 다시 가이드로 평가해
시황·손실한도·가격 무효화선을 만든 뒤에만 주문 요청이 가능합니다.

`이번 한주`, `이번 달`, `오늘만`처럼 기간을 명시한 설정은 각각 저장 시점부터 7일,
31일, 1일 동안만 유효합니다. 만료된 설정은 장 마감 자동평가·신규 가이드·주문에
사용되지 않으며 사용자가 새 조건을 다시 보내야 합니다. 승인 전략의 실제
개인 배분이 0%인 경우 강한 신호가 있어도 신규매수를 제안하지 않고, 배분이 40%라면
첫 진입 비중도 전체 자산 기준으로 비례 축소합니다. 보유 포지션의 손절·매도 안전 판단은
배분이 0%여도 계속 작동합니다.

주문 횟수는 한국 거래일 기준으로 계산되며 프로세스를 재시작해도 SQLite 체결 기록에서
복원됩니다. 따라서 재시작으로 사용자별 또는 전체 일일 주문 한도를 우회할 수 없습니다.

## 토스증권 설정

```powershell
$env:TOSSINVEST_CLIENT_ID='...'
$env:TOSSINVEST_CLIENT_SECRET='...'
$env:TOSSINVEST_ACCOUNT_SEQ='...'
```

봇 실행에 필요한 추가 설정:

```powershell
$env:AGENT_DATA_DIR='E:\work\data'
$env:AGENT_EXECUTION_ENV='mock'
$env:AGENT_LIVE_TRADING_ENABLED='false'
$env:TOSSINVEST_LIVE_ORDERS='false'
$env:AGENT_MAX_ORDER_NOTIONAL='1000000'
$env:AGENT_MAX_ORDERS_PER_DAY='5'
# 사용자가 투자금을 입력하지 않은 경우의 배분·손실예산 참고 기준
$env:AGENT_ACCOUNT_EQUITY_KRW='10000000'
$env:DAILY_GUIDE_HOUR_KST='9'
$env:DAILY_GUIDE_MINUTE_KST='10'
$env:PAPER_INITIAL_CAPITAL_KRW='10000000'
$env:PAPER_EVALUATION_MAX_SYMBOLS='20'
$env:INTRADAY_MINIMUM_BARS='300'
$env:INTRADAY_ARCHIVE_MAX_SYMBOLS='5'

$env:MIRAE_PAPER_COMMISSION_RATE='0.00015'
$env:PYTHONPATH='src'
python -m stock_guide_agent.cli --run-bot
```

실행 전에는 비밀값을 출력하지 않는 준비 점검을 먼저 실행합니다.

```powershell
python -m stock_guide_agent.cli --doctor
```

연결 확인만 하려면 `--once`를 함께 사용합니다. 토스 액세스 토큰은 만료 직전에
자동으로 갱신되며, 텔레그램 업데이트 하나가 실패해도 다음 메시지는 계속 처리됩니다.

### Docker 상시 실행

실제 비밀값은 저장소에 넣지 않고 `.env.example`을 복사한 로컬 `.env`에만 입력합니다.
기본 설정은 모의주문이며 두 개의 실주문 활성화 플래그가 모두 `false`입니다.

```powershell
Copy-Item .env.example .env
# .env에 Telegram·Toss 값을 입력한 뒤 준비 상태 확인
docker compose run --rm stock-guide-agent --doctor
docker compose up -d
docker compose logs -f stock-guide-agent
```

컨테이너는 비루트 사용자, 읽기 전용 루트 파일시스템, 전체 Linux capability 제거,
재시작 정책을 사용합니다. SQLite 데이터만 `stock-guide-data` 볼륨에 보존됩니다.

정기 작업은 SQLite에 다음 실행 시각과 연속 실패 횟수를 저장합니다.

- 보유종목 현재가: 1분 주기
- 토스 계좌 일일 손익·자동 킬스위치: 계좌번호가 있으면 1분 주기
- 모의계좌 종가 평가: 매시간 확인, 한국 거래일 15:40 이후 하루 한 번 불변 기록
- 사용자별 보유·관심종목 전략 평가: 매시간 확인, 장 마감 후 종목별 하루 한 번
- KOSPI 변동성 관리 독립 모의모델: 매시간 확인, 장 마감 후 하루 한 번
- KOSPI 200거래일 장기 절대모멘텀 독립 모의모델: 매시간 확인, 장 마감 후 하루 한 번
- KOSPI와 사용자 보유·관심종목 1분봉 감사 저장: 매시간 확인, 장 마감 후 하루 한 번
- KOSPI·KOSDAQ 투자자 수급: 15분 주기
- 미국 대표 ETF(SPY·QQQ) 가격·일봉 모멘텀: 15분 주기
- OpenDART 공시: API 키가 있으면 5분 주기
- ECOS 거시지표: API 키와 조회 항목이 있으면 일 1회
- 승인 전략 상태 점검: 주 1회
- 30일 증거 충족 전략 장기 이력 재검증: 월 1회(토스 수정 일봉을 최대 2,000개까지 페이지 조회)
- Crossref 신규 학술 전략 메타데이터 탐색: 월 1회
- 외부 전략 리서치 검토 큐: 90일 주기
- NAVER API HUB 중대 뉴스 교차검증: 키가 있으면 30분 주기

```powershell
$env:OPENDART_API_KEY='...'
$env:ECOS_API_KEY='...'
# code,cycle,item,polarity 형식. 상승이 위험선호면 1, 위험회피면 -1
# polarity를 생략한 원자료는 저장하지만 거래 가이드 점수에는 넣지 않음
$env:ECOS_QUERIES='STAT_CODE,D,ITEM_CODE,1;OTHER_CODE,M,ITEM_CODE,-1'
$env:OVERSEAS_BENCHMARK_SYMBOLS='SPY,QQQ'
$env:NAVER_API_HUB_CLIENT_ID='...'
$env:NAVER_API_HUB_CLIENT_SECRET='...'
$env:NEWS_MAX_SYMBOLS='20'
$env:CROSSREF_DISCOVERY_ENABLED='true'
$env:CROSSREF_DISCOVERY_ROWS='20'
# 선택사항이지만 Crossref polite pool 사용을 위해 권장
$env:CROSSREF_MAILTO='owner@example.com'
```

Crossref 탐색은 공개 논문의 DOI, 제목, 저자, 발행일 메타데이터만 가져옵니다. 거래·주식·
포트폴리오 관련 단어와 모멘텀·팩터·변동성·알고리즘 같은 방법 단어가 함께 있는 후보만
중복 제거해 검토 큐에 넣습니다. 소유자는 텔레그램에서 `연구후보`로 확인할 수 있습니다.
후보는 자동 승인되지 않으며 구현, 한국시장 비용 반영 백테스트, 워크포워드와 모의투자를
모두 통과하기 전에는 가이드나 주문에 사용되지 않습니다.

자동 검증을 모두 통과해도 전략 상태는 `승인대기`에서 멈춥니다. 지정 소유자만
`전략승인 <strategy_id> <version>`으로 정확한 버전을 활성화할 수 있고,
`전략중지 <strategy_id> <version>`으로 즉시 배분·가이드 사용을 중단할 수 있습니다.
활성화와 중지에는 소유자 Telegram user ID와 시각이 감사 기록으로 남습니다. 전략이
활성화된 뒤에도 각 주문은 별도의 일회용 코드로 소유자 승인을 다시 받아야 합니다.

API 장애는 지수 백오프 후 3회 연속 실패하면 해당 작업의 회로를 열어 요청 폭주를
막습니다. 리서치 큐에 들어간 자료는 자동 승인되지 않으며 한국시장 재검증을 별도로
통과해야 합니다.

실주문은 지원하지 않으며 과거 활성화 플래그를 설정해도 실제 주문 전송은 차단됩니다.
`AGENT_EXECUTION_ENV=mock`으로 운영하고 내부 모의주문은 모의 체결 영수증만 생성합니다.
계좌가 연결되면 공식 보유자산 응답의 일일 손익률을 매분 확인합니다. 사용자 설정
손실한도 또는 시스템 손실한도에 도달하면 신규 가이드·주문 승인을 중단하며, 주문 제안
후 승인 전에 손실이 악화된 경우에도 승인 시점에 다시 검사합니다. 계좌 API 장애 중에도
신규 거래는 차단됩니다.
현재가(`/api/v1/prices`), 수정 일봉(`/api/v1/candles`), KOSPI·KOSDAQ 수급
(`/api/v1/market-indicators/{symbol}/investor-trading`)은 토스 공식 스키마를 사용합니다.
최근 20거래일 수정주가에서 지지·저항 범위를 계산해 저가 진입 참고선과 고가
분할매도 참고선을 함께 표시합니다. 이 값은 기술적 참고구간이며 미래 고점·저점
예측이나 수익 보장이 아닙니다.
공시·거시·뉴스·해외시장 자료는 출처 URL, 관측 시각, 정규화 점수가 검증된 항목만
가이드에 합산합니다. 뉴스는 NAVER API HUB 최신 규격을 사용하며, 단일 기사의 감성을
추측하지 않습니다. 서로 다른 매체 2곳 이상이 상장폐지·횡령·거래정지·자사주 소각 같은
중대 사건을 같은 방향으로 보도할 때만 낮은 가중치로 반영합니다. 해소·철회·무혐의 표현과
긍정·부정 충돌은 제외하고, 오래된 자료도 카테고리별 유효시간이 지나면 자동 제외됩니다.

공개 알고리즘 원문은 90일마다 최대 2MB 범위에서 SHA-256 지문을 비교합니다. 최초 확인
또는 원문 변경이 있을 때만 리서치 검토 큐를 만들므로 불필요한 모델 호출을 줄입니다.
검토 완료 이력은 별도 감사 테이블에 남지만, 원문 확인만으로 전략을 승인하지 않으며
한국시장 백테스트·워크포워드·비용 반영·30일 이상 모의투자를 다시 통과해야 합니다.
Warren Buffett의 Berkshire 공식 연차서한과 Howard Marks의 Oaktree 원문도 공개 원칙으로
등록되어 있지만, 재현 가능한 거래 규칙이 아니므로 설명과 위험관리 참고에만 사용하고
주문 전략으로 승인하지 않습니다. 또한 모멘텀 검증 결과를 팩터 등 다른 전략에 붙여
승인하지 못하도록 전략별 구현 엔진을 일치시켜 검사합니다.

가이드의 `검증 전략 조합`에는 승인 전략의 공개 원문 제목·연도·URL, 원 연구시장,
한국시장 적용 한계와 마지막 원문 확인일을 함께 표시합니다. 90일 정기 원문 점검에서
이미 기준선을 등록한 승인 전략의 내용이 달라지면 해당 버전을 즉시 중지하고 재검토
큐로 보냅니다. 최초 원문 등록은 기준선 생성이므로 그 자체로 전략을 중지하지 않으며,
변경된 원문을 확인했다는 사실만으로 다시 승인하지도 않습니다.

장기 버킷에는 Moskowitz·Ooi·Pedersen의 공개 논문에 나온 12개월 시계열 모멘텀을
레버리지 없는 long/cash 규칙으로 보수적으로 변형한 `long_term_absolute_momentum`을
사용합니다. 120·200·252거래일 후보를 워크포워드로 비교하고, 200거래일 실시간 신호는
별도 모의원장에 매일 기록합니다. 장기 비중이 스윙·단타 합계 이상이면 종목 가이드도
장기 엔진을 대표 전략으로 선택합니다. 혼합 배분에서는 대표 전략의 실제 승인 비중만큼
첫 진입 크기를 제한합니다.

단타 전략은 현재 검증 전 모의운영 단계입니다. 공개된 장중 모멘텀·오프닝 레인지 연구는
주로 미국·중국·대만 등 다른 시장에 기반하므로, 한국시장 분봉 이력과 호가·슬리피지·체결률을
충분히 확보하기 전에는 단타 비중을 승인 전략으로 가장하지 않고 현금 대기로 둡니다.
초기 모델은 고정 5분 오프닝 레인지의 상향 돌파만 다음 1분봉 시가에 진입하고, 레인지
하단 손절 또는 장 마감에 청산하는 레버리지 없는 long-only 규칙입니다. 매수·매도 수수료,
매도세와 양방향 슬리피지를 모두 차감하며 같은 날 한 번만 거래합니다. 매일 결과를 별도
불변 모의원장에 복리로 기록하고 `모의현황`에서 종목별 최신 결과와 30일 충족 여부를 봅니다.
장 마감 후 KOSPI와 사용자 종목을 기본 5개까지 공식 토스 1분봉으로 저장합니다. 하루
300개 미만이면 완전한 검증일로 인정하지 않고 재시도하며, 같은 시각의 OHLCV가 기존
감사 기록과 달라지면 덮어쓰지 않고 오류로 중단합니다. 이미 완전한 날짜·종목은 API를
다시 호출하지 않습니다. 정상 모의기록 30일과 한 종목의 완전 분봉 378거래일 이상이
쌓이면 월간 워크포워드 검증에 자동 진입하지만, 통과해도 소유자의 `전략승인` 없이는
활성화되지 않습니다.

## 미래에셋증권

사용자는 `증권사 미래에셋`으로 브로커를 선택할 수 있으며 가이드와 소유자 승인형
모의주문을 이용할 수 있습니다. 미래에셋증권 공식 안내에는 영업점 신청 후 제공되는
AnyLink 조회·잔고·주문 연동과 별도 심사를 거치는 FIX/API·DMA가 있습니다. 공개형
REST 명세를 임의 추정하지 않고, 신청 후 받은 정식 모듈·계약 명세에 맞춘 어댑터가
필요하지만 현재는 실거래 어댑터 개발을 범위에서 제외하며, 어댑터가 제공되어도
실주문을 차단합니다. GUI 자동 클릭이나 비공개 엔드포인트는 주문
경로로 사용하지 않습니다.

## 전략 검증

- 시그널은 전일 종가까지만 사용하여 다음 구간에 적용합니다.
- 토스 공식 캔들 API의 200개 제한은 `nextBefore` 커서로 안전하게 페이지 조회합니다.
  중복 봉은 거래일로 제거하고 반복 커서나 상충 종가는 검증 오류로 차단합니다.
- 변동성 관리 엔진은 전일까지의 실현변동성으로 다음 날 노출을 0~100% 범위에서만
  조절합니다. 레버리지는 금지하며 작은 변화는 재조정하지 않아 비용을 제한합니다.
- 변동성 관리는 개별 종목 선정 신호가 아닌 위험 오버레이로 취급합니다. 별도의
  워크포워드와 모의검증을 통과해 전략이 승인된 뒤에만 사용자 배분에 적용합니다.
  API·비용 데이터가 정상이고 사고가 없는 최근 3일 이내 신호만 승인 전략 배분에
  노출배수를 곱하며, 줄어든 비중은 현금으로 이동합니다. 미승인·오래된·비정상 신호는
  사용자 배분과 주문에 아무 영향도 주지 않습니다.
- 독립 모의모델은 전날 목표 노출로 당일 지수 수익을 계산하고 장 마감 재조정 비용을
  차감합니다. `모의현황`에서 다음 날 목표 노출과 일일·누적 성과, 30일 진행률을 확인합니다.
- 모든 검증 보고서는 사용한 신호 엔진을 저장합니다. 전략 ID만 바꾼 보고서나 과거의
  엔진 정보 없는 승인 기록은 실패 폐쇄 방식으로 거부·정지합니다.
- 수급 근거에는 외국인·기관·개인 순매수 금액을 각각 보존해 메신저 시황 요약에
  표시하며, 방향 점수는 외국인과 기관의 합산 순매수를 전체 매수대금으로 정규화합니다.
- 표본외 워크포워드 결과에 수수료·매도세·양방향 슬리피지를 차감합니다.
- 토스 KRX 비용 프로필은 2026년 공개 수수료 0.015%와 매도세 0.20%를 사용합니다.
- 미래에셋 수수료는 고객 계약마다 달라 사용자가 실제 적용률을 입력해야 합니다.
- 과거 구간에 현재 비용을 투영할 경우 보고서에 해당 가정을 명시합니다.
- 월간 자동 재검증은 30개 정상 거래일 증거가 있는 구현 전략만 대상으로 하며, 현재
  공개 비용을 과거 구간에 투영하는 가정을 사용합니다. 통과 결과도 `승인대기`일 뿐
  소유자 명령 없이는 활성화되지 않습니다.
- 모의투자 일수는 봇이 실제로 생성한 전략별 가이드 평가 증거에서만 계산합니다.
  사용자가 수기로 넣은 일별 집계는 감사 기록으로 남지만 30일 검증 요건에는 포함하지
  않으며, API 장애나 중대 사고가 한 번이라도 기록된 한국 거래일도 정상 일수로
  인정하지 않습니다.
- 소유자가 승인해 모의 체결된 주문은 제안 ID, 사용자, 증권사, 전략 버전, 종목,
  수량·가격과 체결 시각을 별도 원장에 기록하며 같은 제안의 중복 기록을 막습니다.
- 모의계좌는 초기자본, 현금, 보유수량, 당일 종가, 수수료·세금·슬리피지, 평가금액,
  일일 손익률과 누적수익률을 체결 원장에서 재현합니다. 같은 날짜의 값은 최초 종가
  평가 후 변경되지 않습니다.
- 매수 주문은 고정 주문금액 상한뿐 아니라 계좌 평가금 대비 가이드 비중과 숫자형
  무효화 가격까지 사용해 예상손실이 거래당 손실예산을 넘지 않는지 검사합니다.
  실거래는 계좌 평가금 또는 숫자형 무효화선이 없으면 차단하며, 승인 직전 계좌 평가금이
  줄어든 경우 배분과 손실예산을 다시 계산합니다. 부분매도는 제안 비율과 저장된 보유수량,
  전량매도는 저장된 보유수량을 초과할 수 없습니다. 소유자 승인 메시지에도 비중·손실한도·
  가격 무효화선을 함께 표시합니다.
- 전략 검증 일수는 같은 한국 거래일에 정상적인 전략 평가 증거와 비용이 완전한
  모의계좌 종가 평가가 모두 있을 때만 증가합니다. 사용자가 직접 요청한 가이드와
  장 마감 후 자동 평가 모두 종목별 하루 한 건으로 중복 제거됩니다. 자동 평가는
  주문이나 승인 요청을 만들지 않습니다.
