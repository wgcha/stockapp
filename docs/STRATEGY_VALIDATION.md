# 전략 검증과 보고서 읽기

이 문서는 전략 검증 도구의 규칙과 확인 범위를 설명한다. 코드와 로컬 테스트가 통과한 것은
실제 투자 성과, 실계좌 연동, 전략별 증거 누적 또는 전략 활성화를 뜻하지 않는다. 실제 매매는
사용자가 증권사 앱에서 직접 하며, 봇은 주문을 실행하지 않는다.

## 소유자 보고 명령

허용된 소유자는 Telegram에서 아래처럼 특정 전략의 버전을 조회할 수 있다.

```text
전략보고 time_series_momentum 1.0.0
```

보고서는 상태, 최근 검증 날짜, 연결된 원장에서 다시 계산한 현재 정상 모의일수 `/30`, 최근
검증 스냅샷의 표본 기간·거래 수·표본 외/워크포워드 여부·비용 반영 Sharpe·최대 낙폭·파라미터
안정성·보고서 모의일수, 비용 반영 표시·출처 URL·가정, 미충족 요건을 보여준다. 원장 또는 거래일
달력이 연결되지 않으면 정상일수는 확인 불가로 표시한다. 비용 출처나 가정이 보고서에 없으면
`자료 없음`이라고 표시한다. 크거나 추가인 출처·가정은 생략 수를 표시한다.

여기서 최근 검증의 모의일수는 저장 당시의 스냅샷이고, `/30` 진행은 현재 내부 원장 자료를
거래일 기준으로 다시 센 값이다. 둘은 서로 다른 시점의 근거다. `기술 검증 통과`는 `승인대기`이며
전략이 활성화됐다는 뜻이 아니다. 신규 활성화는 소유자의 별도 `전략승인 <ID> <버전>` 명령을
요구한다. `전략현황`은 버전별 미검증·미충족 요건을 간단히 표시한다.

`모의현황`과 전략 보고의 현재 정상일수는 내부 모의모델 또는 모의 포트폴리오 기록이다. 실제
계좌 잔고나 손익으로 해석하지 않는다.

## 로컬 오프라인 보고

기존 데이터 디렉터리에 저장된 전략 보고서를 인증정보 없이 조회할 수 있다.

```powershell
$env:PYTHONPATH='src'
python -m stock_guide_agent.cli --strategy-report time_series_momentum 1.0.0 --data-dir .\data
```

`--data-dir`에는 기존 데이터 디렉터리를 지정한다. 생략하면 `AGENT_DATA_DIR`, 그것도 없으면
현재 디렉터리를 사용한다. 다른 로컬 설정과 달력 보정값을 불러오려면 `--env-file .env`를 추가할
수 있다. 명시한 `--data-dir`가 `AGENT_DATA_DIR`보다 우선하며, `KRX_CALENDAR_OVERRIDES`는
동일한 환경 설정에서 읽는다. 보고 조회는 Telegram/Toss 인증정보를 요구하지 않고 런타임을
기동하거나 네트워크에 연결하지 않는다.

조회에는 기존 `strategies.sqlite3`와 정확히 일치하는 전략 ID·버전이 필요하다. 기본 DB가 없거나
전략·버전이 없으면 고정 오류를 출력하고 exit 1로 끝난다. 모의 원장 DB가 없으면 현재 모의일수는
`미연결, 확인 불가`로 표시한다. 원장 형식이 잘못됐거나 KRX 세션을 확인할 수 없으면 0일로
간주하지 않고 `모의검증 근거 확인 불가`로 표시한다. 정상일수는 조회 시점의 KST 날짜를 상한으로
하고, 제공된 거래 달력에서 세션으로 확인된 날짜만 센다.

보고서는 기존 저장 검증 스냅샷과 현재 원장의 `/30` 진행을 함께 표시한다. 저장 시점의 보고서
모의일수와 오늘 다시 센 현재 모의일수는 서로 다른 값이다. 각 SQLite DB는 읽기 전용으로 열지만
여러 DB를 하나의 원자적 스냅샷으로 묶지는 않는다. 일관된 시점의 결과가 필요하면 봇을 중지하거나
오프라인 백업 복사본으로 조회한다.

## 정상 모의일수

- 일반 전략의 사용자 경로는 동일한 전략·버전·사용자·거래일에 정상 전략 평가와 정상 자산 평가가
  모두 있어야 해당 날짜를 센다. 평가·자산 자료의 건강성 검사는 해당 전략·버전·날짜의 자료 전체를
  확인하므로, 어느 사용자의 잘못된 평가나 자산 평가가 있으면 그 날짜의 사용자 증거는 제외될 수
  있다. 별도의 공용 모델 경로는 독립적으로 판정한다. 같은 날짜에 정상 공용 모델 자료가 있으면
  사용자 증거가 빠져도 그 모델 날짜는 인정될 수 있다.
- 장중 전략은 해당 전략·버전·날짜에 저장된 모든 종목 기록이 정상이고 비용 반영·자료 조건을
  만족해야 하루로 센다. 한 종목이라도 건강성·비용·자료 검사가 실패하면 그 날짜는 제외한다.
- 일반 모의일은 30개의 고유한 거래일이면 되며 연속일 필요는 없다. 장중 전략도 정상 모의일수
  30일이 필요하다. 미래 날짜는 제외하고, 연결된 KRX 거래 달력에서 세션으로 확인되지 않는 날짜는
  세지 않는다. 달력을 확인할 수 없으면 서비스는 진행 상황을 확인 불가로 표시하고 새 활성화를
  거부한다.
- 장중 백테스트에는 별도 과거 분봉 자료 조건이 있다. 스케줄 검증은 종목별로 최소 바 수를 갖춘
  완전한 거래일이 378일 이상인 자료를 찾는다. 현재 기본 최소 바 수는 하루 300개이며 날짜는
  기준일까지의 거래 세션만 센다. 이는 실제 장중 실증 자료가 현재 확보됐다는 뜻이 아니다.

## 보고서 검증과 활성화

검증 보고서의 표본 기간·Sharpe·낙폭·안정성 값은 유한한 숫자여야 한다. 표본 기간은 0 이상,
낙폭과 안정성은 0에서 1 사이여야 한다. 워크포워드 구간·거래 수·보고서 모의일수는 0 이상의
정수여야 하며 `bool`과 소수 카운트는 허용하지 않는다. 표본 외 여부·비용 포함 여부·누수 검사
결과는 실제 Boolean 값이어야 한다. NaN, 무한값, 잘못된 형식이나 범위는 `invalid_validation_metrics`
사유로 거부된다. 유효한 음수 Sharpe는 형식 오류가 아니지만 최소 기준을 통과하지 못한다.

그 밖의 통과 기준은 전략 신호 엔진과 ID/버전 일치, 실행 가능한 규칙, 표본 외 테스트, 최소 3개
워크포워드 구간, 비용 조정 Sharpe 0.5 이상, 최대 낙폭 25% 이하, 안정성 0.6 이상, 현실적인
수수료·세금·슬리피지 반영, 누수 검사 통과 및 전략별 표본·거래 수 기준이다. 표본은 일반 전략
5년, 장중 전략 2년 이상이다. 최소 거래 수는 장중 200건, 장기 10건, 그 밖의 전략 50건이다.
공개 원칙이나 구현되지 않은 신호 엔진은 보고서만으로 통과하지 않는다.

연결된 해당 원장이 있는 런타임에서 **새로운** 활성화를 할 때 현재 정상 모의일수가 30일 미만이면
활성화를 거부한다. 달력 근거가 없거나 계산할 수 없는 경우도 거부한다. 일반 전략은 paper ledger,
ORB 전략은 intraday ledger를 사용한다. 관련 원장이 전혀 연결되지 않은 테스트·내부 경로에서는
SQLite store의 기존 API가 유효한 최신 검증 스냅샷을 기준으로 명시적 소유자 승인을 허용할 수 있다.
따라서 그 API를 실제 런타임의 현재 원장 점검과 혼동하지 않는다.

과거에 이미 활성화된 버전은 정상일수 재계산만으로 자동 중지되지 않는다. 운영자는 해당 버전을
`전략보고`로 다시 검토하고 새 원장 근거를 확인해야 한다. 과거 승인 보고서를 다시 읽었을 때 숫자
형식·유한성 검증이 실패하면 해당 승인 상태는 중지로 낮아진다. 실제 성과를 확인하거나 과거
활성화 상태를 다시 승인한 것은 아니다.

## 내부 중단 스위치 영속성

소유자의 가이드·내부 연구 중단 스위치 활성 여부와 사유는 기존 `users.sqlite3`의
`execution_safety_state`에 저장되며 기존 SQLite 백업에 포함된다. 활성화는 저장 콜백을 즉시
수행한다. 재설정은 DB에 해제 상태를 먼저 저장한 뒤 메모리를 해제한다. 저장이 실패하면 메모리
중단을 유지하고 고정 오류를 반환한다. 단, 저장되지 않은 상태는 프로세스 종료 후 복구할 수 없고,
이 변경 전에 메모리에만 있던 중단 상태도 복구할 수 없다. DB에 잘못된 상태가 있거나 시작 시
상태를 읽을 수 없으면 런타임은 시작을 거부한다. API 건강성, 일일 손익, 제안 등 다른 일시 상태는
재시작 후 복원하지 않는다.

## 검증 기록과 남은 범위

2026-10-07 번들 Python 전체 unittest는 317개 중 316개 통과, 1개 skip이다. 이는 로컬 코드 회귀
검증이며 실제 Telegram 메시지, 시세·계좌 API, 장중 실자료, 실제 전략 승인, 배포 또는 연속 운영
검증은 포함하지 않는다. 30 정상 모의일, 장중 378 세션 과거 바, 실제 활성화는 운영 자료가 쌓인
뒤 별도로 확인해야 한다. 최신 전체 범위와 기록은 [개발 계획](DEVELOPMENT_PLAN.md),
[변경 기록](CHANGELOG.md), [4단계 운영 인수](DEPLOYMENT_ACCEPTANCE.md)를 참고한다.

2026-10-08 전체 unittest는 337개 중 336개 통과, 기존 Windows 심볼릭 링크 권한 문제로 1개 skip이다.
Sol 검수와 Astra의 SQL 근거 집계·손상 DB 독립 검수가 통과했다. WAL 최신 보고 날짜와 근거 수 표시를
확인했고 로컬 보고 테스트 12개가 통과했다. 이 검증은 실제 Telegram 메시지, API, 전략 성과, 배포
또는 연속 운영을 포함하지 않는다. 정상 모의일수 SQL의 `typeof` 검사는 금융 지표의 TEXT/BLOB
강제 변환만 방지하며 다른 SQLite 값의 형식까지 검증하는 것은 아니다.
